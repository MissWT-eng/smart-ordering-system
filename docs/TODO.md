### 下一轮建议顺序

1. **会话续期**：先明确滑动有效期规则。有效且归属校验通过的请求刷新会话 TTL；过期或越权请求不能续期，也不能悄悄重建旧会话。归属检查与刷新需协调为原子操作，并覆盖与清理竞争的情况。
2. **同会话并发与生命周期验收**：确定同时发送两条消息时采用串行处理或明确拒绝；补测续期、注册用户隔离及重启后上下文丢失的提示。当前使用计数只保护清理，不能代替消息执行顺序控制。
3. **注册用户长期画像**：优先用 MySQL 保存少量结构化偏好，从明确的“记住我的偏好”开始；先做本人画像查看、修改、删除，再接入聊天读取和工具写入。
4. **画像与推荐结合**：区分本轮临时要求与长期偏好，使用可信用户身份；已有反馈重排继续复用，不能把一次预算或一次点菜直接推断为长期习惯。
5. **流式响应与前端**：在生命周期与确认流程稳定后接入 SSE 和增量展示。

### 依赖与边界

- 会话记忆不能替代订单确认与后端鉴权；正式下单仍需明确确认和业务校验。
