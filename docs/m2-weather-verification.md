# M2 天气工具与 Redis 共享缓存验证记录

验证日期：2026-10-22。结论：门店当前天气查询、推荐辅助、失败降级及共享短时缓存通过本轮分阶段验证。

## 实现范围

- `DishTools.queryWeather()` 返回 `WeatherToolResult`，状态为 `SUCCESS` 或 `SERVICE_UNAVAILABLE`；天气事实由 `WeatherInfoDTO` 承载。
- DTO 保留城市、天气描述、摄氏温度、观测时间 `obsTime` 和后端获取时间 `obtainTime`。城市编号、名称来自 YAML，当前为长春。
- `obtainCurrentWeather()` 统一读取缓存、请求天气、写入缓存；`fetchCurrentWeather()` 负责供应商请求、gzip 处理、数据校验及异常转换。
- 推荐使用的 `getCurrentWeather()` 调用统一入口，仅转换成字符串；天气不可用时返回空值，让推荐继续按已有口味和预算执行。
- Redis Key 为 `weather:current:<cityId>`，Value 为 DTO JSON；`weather.cache-ttl-seconds` 当前为 300 秒。命中不续期、不更新两个时间字段；只缓存成功结果。
- 缓存读取、解析或字段校验失败时回源；写缓存失败仍返回取得的天气；上游失败保留天气业务异常。
- `GET /weather` 使用同一 Service；当前受用户令牌拦截器保护。游客可以通过公开的 Agent 入口查询天气。

## 天气工具与失败场景

真实模型及真实天气服务验证了同步天气查询、先查天气再推荐，以及流式天气回复。工具执行结果中的城市、温度和观测时间与回复核对一致。

在独立测试上下文中模拟天气服务不可用，验证工具返回 `SERVICE_UNAVAILABLE` 且天气为空；模型如实说明不可用，不生成温度。需要推荐时仍调用推荐工具，返回的菜品与数据库在售状态、不辣条件及单价预算核对一致。其他业务异常继续向外抛出。

本地 HTTP 替身另覆盖普通 JSON、gzip、上游业务错误、缺少 `now`、字段不完整、非法时间、非法 JSON、HTTP 错误及读取超时；正常数据解析成功，失败统一转换为天气业务异常。未通过修改用户正在运行的服务配置模拟故障。

## 缓存边界：12 项通过

以下检查使用最新实现、隔离的 HTTP 替身、Redis 测试替身及独立真实 Redis Key，不调用真实模型：

| 检查 | 结果 |
| --- | --- |
| 有效缓存直接返回，保留获取时间，不请求上游、不重写缓存 | 通过 |
| Redis 读取异常后继续请求天气 | 通过 |
| 非法 JSON、JSON `null`、空字符串、空白、空对象、字段不完整，共 6 项 | 均回源，未抛缓存解析异常 |
| Redis 写入失败仍返回真实天气 | 通过 |
| 未命中后写入成功结果，并设置 300 秒 TTL | 通过 |
| 上游失败保留业务异常，不写入缓存 | 通过 |
| 真实 Redis 中，不同入口共用结果、命中不续期、过期后重新请求 | 通过 |

真实 Redis 过期检查使用独立城市 Key 和 2 秒测试有效期，避免等待生产配置的 300 秒，也不改变门店缓存配置。测试结束后该 Key 已删除。

## 重启后的真实 HTTP 联调

用户重启 Spring Boot 后，通过正在运行的 8080 服务执行 4 次请求，使用不同会话及两份独立游客 Cookie。这样不会把同一段聊天中的天气复述当成缓存验证。

测试开始时门店天气 Key 不存在，第一次请求后生成缓存：

```json
{
  "cityName": "长春",
  "weatherDescription": "晴",
  "temperature": "8",
  "obsTime": "2026-10-22T22:37:00",
  "obtainTime": "2026-10-22T23:00:29.5711485"
}
```

| 请求 | 缓存剩余 TTL | 核对结果 |
| --- | --- | --- |
| 游客 A 第一次查询天气 | 约 298.9 秒 | 生成缓存，回复与数据一致 |
| 游客 A 新会话再次查询天气 | 约 297.3 秒 | JSON 和时间字段完全一致，未续期 |
| 游客 B 新会话结合天气推荐 | 约 290.9 秒 | 推荐链路复用同一缓存，只展示候选及单价 |
| 游客 B 通过 `/agent/chat/stream` 查询天气 | 约 288.9 秒 | 收到有效 SSE `done`，复用同一缓存 |

四次响应均无草稿、订单或画像候选结果。检查前后 `orders`、`order_item`、`user_preference`、`recommendation_log`、`user`、`user_dish_feedback` 六张表记录数和订单草稿 Key 集合一致。4 个专用 Redis 会话 Key 已删除，内存记忆由服务既有过期清理机制回收；有效的公共天气缓存保留供正常使用。

## 当前边界

- 仅支持配置的门店当前天气；任意城市、预报和语音功能尚未实现。
- 300 秒是缓存存活时间，不保证上游观测发生在最近 300 秒内；结果保留真实观测时间，目前没有单独的最大观测年龄校验。
- 缓存未命中的并发请求可能重复回源，当前没有增加分布式锁或回源合并；是否补充按配额与实际负载再评估。
- 外部请求仍沿用和风天气 V7，供应商接口迁移单独推进。
- 本轮不代表全部历史手工用例、完整 V1 业务回归或生产容量测试已经完成。
