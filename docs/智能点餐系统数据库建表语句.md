# 智能点餐系统数据库建表语句

## 新建数据库的建表参考

订单表包含 V2 草稿关联字段及唯一约束，与当前订单 Mapper 对齐。草稿报价保存在 Redis，正式订单落库时保存草稿编号和归属。下面的 SQL 用于新建表；已有数据库的草稿字段升级示例见文末。

```sql
-- 1. 用户表
CREATE TABLE `user` (
  `user_id` BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '用户ID',
  `phone_number` VARCHAR(11) NOT NULL UNIQUE COMMENT '手机号',
  `nickname` VARCHAR(50) DEFAULT NULL COMMENT '昵称',
  `user_created_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '注册时间',
  `user_status` ENUM('active', 'disabled') DEFAULT 'active' COMMENT '用户状态',
  `balance` DECIMAL(10,2) DEFAULT 0.00 COMMENT '余额（预留）'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

-- 2. 菜品表
CREATE TABLE `dish` (
  `dish_number` BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '菜品号',
  `dish_name` VARCHAR(100) NOT NULL UNIQUE COMMENT '菜品名',
  `dish_status` ENUM('available', 'unavailable') DEFAULT 'available' COMMENT '今日是否可制作',
  `dish_introduction` TEXT COMMENT '菜品介绍（用于RAG检索）',
  `price` DECIMAL(10,2) NOT NULL COMMENT '价格',
  `category` ENUM('meat', 'vegetable', 'drink', 'soup') DEFAULT 'vegetable' COMMENT '菜品分类',
  INDEX `idx_category` (`category`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='菜品表';

-- 3. 订单主表
CREATE TABLE `orders` (
  `order_num` BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '订单编号',
  `order_user_id` BIGINT COMMENT '下单用户ID',
  `order_total_money` DECIMAL(10,2) NOT NULL COMMENT '订单总金额',
  `order_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '下单时间',
  `order_status` ENUM('pending', 'paid', 'cancelled') DEFAULT 'pending' COMMENT '订单状态',
  `draft_id` VARCHAR(36) DEFAULT NULL COMMENT 'V2草稿编号，同一草稿最多创建一笔订单',
  `draft_owner_key` VARCHAR(128) DEFAULT NULL COMMENT 'V2草稿归属：注册用户或游客会话',
  FOREIGN KEY (`order_user_id`) REFERENCES `user`(`user_id`),
  UNIQUE KEY `uk_orders_draft_id` (`draft_id`),
  INDEX `idx_user` (`order_user_id`),
  INDEX `idx_status` (`order_status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单主表';

-- 4. 订单明细表
CREATE TABLE `order_item` (
  `item_id` BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '明细ID',
  `order_num` BIGINT NOT NULL COMMENT '所属订单编号',
  `dish_number` BIGINT NOT NULL COMMENT '菜品编号',
  `quantity` INT DEFAULT 1 COMMENT '数量',
  `price_at_time` DECIMAL(10,2) NOT NULL COMMENT '下单时价格',
  FOREIGN KEY (`order_num`) REFERENCES `orders`(`order_num`),
  FOREIGN KEY (`dish_number`) REFERENCES `dish`(`dish_number`),
  INDEX `idx_order` (`order_num`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单明细表';

-- 5. AI推荐记录表
CREATE TABLE `recommendation_log` (
  `log_id` BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '日志ID',
  `user_id` BIGINT NOT NULL COMMENT '用户ID',
  `recommended_dishes` JSON DEFAULT NULL COMMENT '推荐菜品编号列表 [1,3,5]',
  `ordered_dishes` JSON DEFAULT NULL COMMENT '实际点餐菜品编号 [1,3]',
  `weather` VARCHAR(20) DEFAULT NULL COMMENT '天气情况',
  `context` JSON DEFAULT NULL COMMENT '上下文特征：{"last_meal":"lunch","season":"summer"}',
  `recommendation_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '推荐时间',
  `feedback_score` TINYINT DEFAULT NULL COMMENT '反馈分数 1-5',
  FOREIGN KEY (`user_id`) REFERENCES `user`(`user_id`),
  INDEX `idx_user_time` (`user_id`, `recommendation_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='AI推荐日志表';

-- 6. 商户操作日志
CREATE TABLE `operation_log` (
  `log_id` BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '日志ID',
  `operator` VARCHAR(50) NOT NULL COMMENT '操作人',
  `operation_type` VARCHAR(20) NOT NULL COMMENT '操作类型 INSERT/UPDATE/DELETE',
  `operation_content` TEXT COMMENT '修改内容详情',
  `operation_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '操作时间',
  INDEX `idx_time` (`operation_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商户操作日志';
```

## V2 草稿字段升级（已有数据库）

本节仅描述订单草稿增量，不代表已核查或升级本地数据库。先用 `SHOW CREATE TABLE orders` 核对现有字段与索引；下面示例适用于两个字段及草稿唯一索引均未添加的数据库。若已部分升级，只执行缺失项，不重复添加。

```sql
ALTER TABLE `orders`
  ADD COLUMN `draft_id` VARCHAR(36) DEFAULT NULL COMMENT 'V2草稿编号，同一草稿最多创建一笔订单',
  ADD COLUMN `draft_owner_key` VARCHAR(128) DEFAULT NULL COMMENT 'V2草稿归属：注册用户或游客会话',
  ADD UNIQUE KEY `uk_orders_draft_id` (`draft_id`);
```

- `draft_id` 来自后端生成的 UUID。V1 手动订单和原有订单保持 `NULL`；MySQL 唯一索引允许多个 `NULL`，不会限制这些订单。
- `draft_owner_key` 与后端的 `ownerKey` 一致，用于重复确认时校验归属；不由模型指定，也不作为面向用户展示的字段。
- 唯一索引约束同一非空草稿编号最多对应一笔订单，配合创建订单事务、重复键异常处理和已有订单查询保护并发确认。
- 若字段已存在但唯一索引缺失，先检查非空 `draft_id` 是否重复；发现重复时先核对订单事实并处理，再添加索引。

```sql
SELECT `draft_id`, COUNT(*) AS `order_count`
FROM `orders`
WHERE `draft_id` IS NOT NULL
GROUP BY `draft_id`
HAVING COUNT(*) > 1;

-- 仅在字段已存在、该唯一索引缺失且没有重复草稿编号时执行。
ALTER TABLE `orders`
  ADD UNIQUE KEY `uk_orders_draft_id` (`draft_id`);
```

约束存在不等于并发验收已通过。仍需验证同一草稿并发确认只产生一笔主订单和一套明细，重复请求返回相同订单编号，其他身份不能读取该订单。
