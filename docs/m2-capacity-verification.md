# M2 本机会话容量限制与收尾记录

验证日期：2026-10-21。

## 实现与边界

- `auth.max-cached-conversations` 默认 100，必须大于 0；Spring 初始化 `ConversationMemoryServiceImpl` 时创建对应数量的 `Semaphore` 许可。
- 新编号首次登记到本地使用记录时获取一个容量许可；容量耗尽返回 `CONVERSATION_CAPACITY_EXCEEDED`，HTTP/code 均为 503，提示“当前会话较多，请稍后再试”。
- 当前请求结束只将使用计数归零，继续保留记忆与容量占用。已有空闲会话续聊复用原许可，容量满时仍可进入；同会话正在处理时仍返回 409。
- 定时任务每轮结束后等待 60 秒，只清理使用计数为零且 Redis 元数据已不存在的会话。清空并移除框架记忆成功后，归还容量许可并移除本地记录；执行中、Redis 检查失败或记忆清理失败时保留记录，后续重试。
- 缓存容量许可与同步、SSE 共享的 4 个在途请求许可分别管理。前者限制本机跟踪的会话总数，后者限制正在执行的聊天请求数；单会话消息窗口仍为 20 条。
- 此上限不是 Redis Key 数量或精确的 JVM 字节上限。新请求先创建 Redis 元数据再申请本地容量，因此被拒绝的新会话也可能留下有 TTL 的元数据。聊天内容仍在本机内存，未增加跨实例共享记忆或重启恢复。

| 分组 | 检查内容 |
| --- | --- |
| 1 | 非正容量配置拒绝初始化 |

| 3 | 新会话满额拒绝，不插入本地记录 |
| 4 | 满额时已有会话可用，同会话重入返回忙碌 |

| 7 | 元数据缺失或读取异常不消耗新许可 |
| 8 | Redis 存在性不确定或异常时保留，恢复后可重试 |
| 9 | 消息清空失败时保留记录及许可占用，随后重试 |
