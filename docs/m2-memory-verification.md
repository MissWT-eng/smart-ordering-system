# 短期会话记忆验证记录

验证日期：2026-10-18 至 2026-10-20。下列记录按实施阶段保留，各轮针对当时的实现验证，不表示最新代码已完成整套自动化回归。

## 实现范围

- `POST /agent/chat` 接收可选 `conversationId`，成功返回 `data.conversationId` 与 `data.reply`。
- 后端生成 UUID，Redis 的 `chat:conversation:<conversationId>` 当前保存包含可信 `ownerKey` 与 `instanceId` 的 JSON；归属及实例校验通过后原子刷新 TTL，默认 30 分钟。
- `@MemoryId` 与 `chatMemoryProvider` 关联独立的 `MessageWindowChatMemory`，窗口为 20 条消息。
- 本地 `ConcurrentHashMap` 跟踪使用状态，同会话同时只允许一条消息进入 Agent，其余返回 409；Controller 在 `finally` 中归还已取得的使用资格。
- 定时任务清理空闲且已过期的会话，清空消息内容、移除框架缓存和本地跟踪记录。
- 当前实例编号不匹配时，本人旧会话返回明确的 409 提示；其他身份优先返回 403。该策略识别内存上下文失效，不恢复消息或提供集群共享记忆。

## 复测提示

1. 启动项目，同一游客的多轮请求保持同一个 Session Cookie；每次回复使用返回的真实编号。
2. 验证身份隔离时使用独立 Cookie 容器，先确认 Session 确实不同；仅新建请求页不能证明身份已切换。
3. 测试过期时只操作本次新建的专用测试会话，确认 Redis Key 已消失，再使用原 Cookie 和旧编号请求；预期 HTTP 404。
4. 验证实际内存清理时，需在受控测试上下文或调试器中同时检查框架记忆和本地计数记录，不能仅以 Redis Key 消失或 HTTP 404 判断已释放内存。
5. 正在回复、故障恢复及竞争场景使用可控等待和同步信号，避免依靠手工同时点击制造时间误差。
6. 当前会话值是 JSON，核对 `ownerKey` 字段而非将整段 GET 返回值当作身份；验证续期前只缩短本轮测试 Key 的 TTL。
7. 验证实例失效只修改专用测试记录的实例编号，保留其归属；检查本人 409、他人 403，以及拒绝后未续期。旧格式缓存也需要单独检查。
